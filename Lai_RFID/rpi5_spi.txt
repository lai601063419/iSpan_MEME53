CPU利用PCIe讀取rp1晶片，並使用DMA(Direct Memory Access，直接記憶體存取)，讓CPU可以把記憶體搬運的工作交給硬體處理

Rpi5 的SPI控制器共有6個

*********************************
spi to RC522

  頻率設定為 5 MHz

  1 Byte 暫存器位址/指令 + 1 Byte 資料
  (寫入 0xxxxxx0， 讀取 1xxxxxx0)

  暫存器
    CommandReg 0x01{
      PCD_IDLE (0x00) — 空閒 / 中斷指令

      作用：取消晶片目前正在執行的任何指令，並將晶片切換至待命（Idle）狀態。
      時機：通常用於發送新指令前的狀態重置，或是當收發超時、發生異常需要強制終止當前動作時。

      PCD_TRANSCEIVE (0x0C) — 發送並接收資料（Transceive）

      作用：將 FIFO 緩衝區中的資料透過天線發送出去，並在發送完成後自動切換為接收模式，等待卡片（PICC）回應。
      時機：RC522 最核心的通訊指令，所有與卡片互動的過程（如尋卡 REQA、防碰撞 Anticoll、選卡、讀寫卡片區段等）都需要呼叫此指令。

      PCD_RESETRST (0x0F) — 軟體重置（Soft Reset）

      作用：重新初始化 MFRC522 內部的控制邏輯與暫存器，將其完全恢復至上電時的預設狀態（但不會影響外部 SPI 匯流排介面）。
      時機：用於程式一開始的晶片初始化流程，或是在傳輸發生不可逆錯誤時進行軟體復原，免去透過物理 RST 引腳拉低電位重置的麻煩。
    }

    BitFramingReg 0x0D{
      傳送給卡片的指令的格式

      0x07: 根據 ISO 14443A 規範，卡片剛進入天線場域時，用來詢問「附近有沒有卡片」的 REQA / WUPA 指令必須是長度恰好為 7 bits 的短訊號（Short Frame）。

      0x00: 1 byte的指令
      
      最高位為1代表傳送FIFODataReg裡的資料給卡片
    }

    TModeReg 0x2A{
      設定定時器，可以用來當作卡片回應逾時的基準
    }

    TPrescalerReg 0x2B{
      設定除頻器
    }

    TReloadRegL 0x2C{
      設定reload的count最大值
    }

    TReloadRegH 0x2D{
      設定reload的count最大值
    }

RC522 to card

  指令
    PICC_ANTICOLL 0x93{
      防碰撞選擇指令（Cascade Level 1），通知感應範圍內的所有卡片準備發送其 UID 的前 4 個 Byte。

      後面會跟著NVB (Number of Valid Bits, 有效位元數){
        高 4 位：代表讀卡機發送了幾個完整 Byte。
        低 4 位：代表 Byte之後 有幾個額外 Bit。
      }
      
      後面不傳送UID，代表要尋找RFID卡
      後面帶著指定的UID，代表選擇指定的RFID卡，並給予它ACTIVE狀態
    }
